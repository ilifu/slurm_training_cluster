# Manage Users Role

This role creates user accounts on cluster nodes, sets up home directories with proper permissions, configures SSH key authentication, and manages sudo access through the wheel group.

## Description

The manage_users role provides comprehensive user account management for the SLURM cluster:
- Creates system groups (`slurm_user`, `slurm_admin`)
- Creates individual user accounts with home directories
- Generates SSH keys (ed25519) for passwordless authentication
- Sets up SSH authorized keys for remote access
- Configures sudoers for passwordless sudo via wheel group
- Ensures home directory security (700 permissions)
- Retries operations for reliability (5 retries, 30-second delays)

The role is optional and only runs when `users` variable is defined.

## Requirements

- Ubuntu 22.04 LTS (Jammy Jellyfish)
- Ansible 2.10 or higher
- Root or sudo access on target nodes
- `home_dir` variable must be defined (e.g., `/users`, `/home`)
- Users must have home directories on a shared filesystem (e.g., `/users` from CephFS)

## Role Variables

### Required Variables

#### `users` - Array of User Definitions

Users to create on the system. The role only runs if this variable is defined.

```yaml
users:
  - username: "alice"             # Linux username (unique)
    uid: 10001                    # Linux user ID (unique, recommended >=10000)
    first_name: "Alice"           # User's first name
    last_name: "Johnson"          # User's last name
    ssh_public_key: "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5..." # Ed25519 public key

  - username: "bob"
    uid: 10002
    first_name: "Bob"
    last_name: "Smith"
    ssh_public_key: "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5..."
```

#### `home_dir` - Base Directory for User Homes

Base path where user home directories are created.

```yaml
home_dir: "/users"  # User homes will be at /users/alice, /users/bob, etc.
```

This should point to the shared CephFS mount (`/users`) so users can access their data from any node.

### Optional Variables

#### `sudoers` - List of Usernames with Sudo Access

Users who should have passwordless sudo access via wheel group membership.

```yaml
sudoers:
  - alice
  - bob
```

If this variable is not defined, no users get sudo access.

## Group Variables

This role typically uses variables defined in group_vars or generated by scripts:

```yaml
# From Terraform or user management scripts
users:
  - username: "training"
    uid: 10000
    first_name: "Training"
    last_name: "User"
    ssh_public_key: "..."

home_dir: "/users"          # CephFS mount point for home directories

sudoers:
  - training                 # Give training user sudo access
```

## Features

### System Groups

The role creates two system groups:

1. **`slurm_user` (GID 5000)** - Default group for regular cluster users
2. **`slurm_admin` (GID 5001)** - Administrative group for cluster administrators

### User Account Creation

For each user in the `users` array:
- Creates individual primary group (named after username with user's UID as GID)
- Creates user account with specified UID
- Sets comment field to "FirstName LastName"
- Adds user to `slurm_user` group for cluster access
- Creates home directory at `{{ home_dir }}/{{ username }}`
- Generates ed25519 SSH key pair
- Uses `/bin/bash` as login shell
- Uses `/etc/skel` as skeleton directory

### SSH Key Management

- Generates ed25519 SSH keys (modern, secure alternative to RSA)
- Public keys stored in `~/.ssh/authorized_keys`
- Sets up SSH public key authentication
- Supports public key from `ssh_public_key` variable

### Home Directory Security

- Ensures home directories have strict permissions: `700` (rwx for owner only)
- Prevents other users from accessing home directories
- Runs with `run_once: true` to avoid redundant operations

### Sudo Configuration

- Creates or verifies `wheel` group exists
- Adds passwordless sudo rule: `%wheel ALL=(ALL) NOPASSWD: ALL`
- Validates sudoers syntax with `visudo -cf` before applying
- Adds specified users to wheel group for sudo access

### Reliability

- All user creation operations retry up to 5 times
- 30-second delay between retries
- Handles transient failures (network delays, temporary locks)

## Dependencies

- **base** - Base OS installation (prerequisite)
- **common** - Installs system packages
- **ceph** - CephFS mount at `{{ home_dir }}` (if using shared storage)

This role should run after ceph mounting if home directories are on CephFS.

## Deployment Order

This role is typically deployed in this sequence:

1. **base** - OS base configuration
2. **common** - System packages
3. **ceph** - Mount CephFS (if using `/users` on shared storage)
4. **manage_users** - Create user accounts
5. Other roles depend on users being present for ownership/permissions

## Installation Process

The role performs these steps in order:

### Phase 1: System Groups
```bash
# Create system groups
groupadd -g 5000 slurm_user
groupadd -g 5001 slurm_admin
```

### Phase 2: User-Specific Groups
For each user, create a primary group:
```bash
groupadd -g 10001 alice
groupadd -g 10002 bob
```

### Phase 3: User Account Creation
For each user in `users` array:
```bash
useradd -u 10001 -g alice -G slurm_user \
  -d /users/alice -c "Alice Johnson" \
  -s /bin/bash -m alice

# SSH key generation happens here
ssh-keygen -t ed25519 -f /users/alice/.ssh/id_ed25519 -N ""
```

### Phase 4: SSH Public Key Setup
Add public key to authorized_keys for each user:
```bash
mkdir -p /users/alice/.ssh
echo "ssh-ed25519 AAAAC3..." >> /users/alice/.ssh/authorized_keys
chmod 700 /users/alice/.ssh
chmod 600 /users/alice/.ssh/authorized_keys
```

### Phase 5: Home Directory Permissions
```bash
chmod 700 /users/alice
```

### Phase 6: Sudo Configuration (if `sudoers` defined)
```bash
# Create or verify wheel group
groupadd wheel

# Add sudoers rule
echo '%wheel ALL=(ALL) NOPASSWD: ALL' >> /etc/sudoers

# Verify syntax
visudo -cf /etc/sudoers

# Add users to wheel group
usermod -aG wheel alice
usermod -aG wheel bob
```

## Example Playbook

To use this role as part of site.yaml:

```yaml
- name: Create user accounts
  hosts: all                        # Can be applied to all nodes or specific groups
  tags: [users]
  vars:
    home_dir: "/users"
    users:
      - username: "alice"
        uid: 10001
        first_name: "Alice"
        last_name: "Johnson"
        ssh_public_key: "ssh-ed25519 AAAAC3..."
    sudoers:
      - alice
  roles:
    - manage_users
```

To run this role explicitly:

```bash
# Create users on all cluster nodes
ansible-playbook site.yaml -i inventory.yml -t users --ask-vault-pass

# Or create users on specific hosts only
ansible-playbook site.yaml -i inventory.yml -t users --ask-vault-pass -l "login_node"
```

## User SSH Key Setup

Users need to provide their public SSH key for the `ssh_public_key` variable. If no pre-existing keys:

```bash
# User generates their own key
ssh-keygen -t ed25519 -C "alice@example.com"

# Get public key
cat ~/.ssh/id_ed25519.pub

# Add to users variable:
ssh_public_key: "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5... alice@example.com"
```

The role will:
1. Create this public key in the user's `~/.ssh/authorized_keys`
2. Also generate a new ed25519 key on the cluster for the user

## Verification

After this role completes, verify user accounts:

```bash
# List all users
getent passwd | grep -E "10[0-9]{3}"

# Check user groups
id alice
id bob

# Verify home directories
ls -ld /users/alice /users/bob

# Check home directory permissions (should be 700)
stat /users/alice

# Verify SSH keys exist
ls -la /users/alice/.ssh/

# Check SSH public key
cat /users/alice/.ssh/authorized_keys

# Test sudo access (if user in sudoers)
sudo -l -U alice

# Verify sudoers configuration
sudo visudo -c

# Test user login via SSH
ssh alice@controller
```

## Troubleshooting

### User Creation Fails with "Home Directory Not Found"

If role fails with "Cannot create users, please ensure the home_dir variable is set":

```bash
# Verify home_dir variable is set
ansible all -i inventory.yml -m debug -a "var=home_dir" -e "ansible_become=false"

# Verify home_dir path exists
ansible all -i inventory.yml -m file -a "path={{ home_dir }} state=directory" -b

# If using CephFS, verify mount
ansible all -i inventory.yml -m shell -a "mount | grep {{ home_dir }}" -b
```

### UID/GID Conflicts

If user creation fails with "UID already in use":

```bash
# List existing users and UIDs
getent passwd

# Find available UIDs (starting from 10000)
awk -F: '$3 >= 10000 {print $3}' /etc/passwd | sort -n | tail

# Update users variable with unique UIDs
```

### SSH Key Not Working

If SSH login fails even with correct key:

```bash
# Verify authorized_keys file exists and is readable
cat /users/alice/.ssh/authorized_keys

# Check permissions
ls -la /users/alice/.ssh/

# Should be:
# .ssh -> 700
# authorized_keys -> 600

# Fix if needed
sudo chmod 700 /users/alice/.ssh
sudo chmod 600 /users/alice/.ssh/authorized_keys
sudo chown -R alice:alice /users/alice/.ssh
```

### Sudo Not Working

If user cannot run sudo commands:

```bash
# Check user is in wheel group
id alice
# Should show: groups=...wheel...

# Verify sudoers rule
sudo visudo -c
grep wheel /etc/sudoers

# Test sudo (should NOT prompt for password)
sudo -l -U alice
```

### Home Directory Permissions Wrong

If home directory is readable by others:

```bash
# Check permissions
stat /users/alice
# Should show: Access: (700/drwx------)

# Fix permissions
sudo chmod 700 /users/alice

# Re-run role to reset all permissions
ansible-playbook site.yaml -i inventory.yml -t users -t homes
```

### SSH Key Generation Issues

If ed25519 keys are not generated:

```bash
# Check if SSH key exists
ls -la /users/alice/.ssh/id_ed25519*

# Generate manually if missing
sudo -u alice ssh-keygen -t ed25519 -f /users/alice/.ssh/id_ed25519 -N ""

# Set correct permissions
sudo chown alice:alice /users/alice/.ssh/id_ed25519*
sudo chmod 600 /users/alice/.ssh/id_ed25519
sudo chmod 644 /users/alice/.ssh/id_ed25519.pub
```

## Configuration

### Adding More Users

To add additional users, update the `users` variable in group_vars or playbook vars:

```yaml
users:
  - existing_users...
  - username: "newuser"
    uid: 10010
    first_name: "New"
    last_name: "User"
    ssh_public_key: "ssh-ed25519 ..."
```

Then re-run the role:

```bash
ansible-playbook site.yaml -i inventory.yml -t users
```

### Removing Users

To remove a user, manually delete them (this role doesn't support deletion):

```bash
sudo userdel -r alice        # -r removes home directory

# Or keep home directory:
sudo userdel alice
```

### Changing Sudo Access

To add/remove sudo access, update the `sudoers` variable:

```yaml
sudoers:
  - alice
  - bob
  - newuser          # Add sudoer
```

Then re-run the role:

```bash
ansible-playbook site.yaml -i inventory.yml -t users -t sudoers
```

## Security Considerations

1. **SSH Keys** - Store in vault.yml when using Ansible Vault
   - Public keys: Can be in version control
   - Private keys: Should be generated locally, not stored in ansible vars

2. **Home Directory Permissions** - 700 (rwx------) is enforced
   - Prevents other users from reading private files
   - Each user can only access their own directory

3. **Sudo Access** - Use passwordless sudo only for trusted users
   - Consider enabling password prompts for sensitive systems
   - Audit sudoers usage regularly

4. **SSH Public Keys** - Rotate and update regularly
   - Remove old/unused keys
   - Replace keys when users leave

5. **UID/GID Assignments** - Use consistent numbering
   - UIDs >= 10000 for regular users (vs system users 0-999)
   - Document UID assignments in group_vars for clarity

## Common Patterns

### Pattern: Generating User SSH Keys

To generate user SSH keys before deployment:

```bash
# For each user, generate a key pair
ssh-keygen -t ed25519 -f alice_id_ed25519 -N ""

# Extract public key
cat alice_id_ed25519.pub

# Add public key to users variable
ssh_public_key: "$(cat alice_id_ed25519.pub)"
```

### Pattern: Bulk User Creation

Create multiple users from a list:

```bash
# users.json
[
  {"username": "alice", "uid": 10001, "first_name": "Alice", "last_name": "Johnson", "ssh_public_key": "..."},
  {"username": "bob", "uid": 10002, "first_name": "Bob", "last_name": "Smith", "ssh_public_key": "..."}
]

# Convert to YAML and use in playbook
```

### Pattern: Sudo Group for Cluster Admins

Create a separate admin group:

```yaml
# In tasks, add before sudoers block:
- name: Add cluster admins to sudoers
  user:
    name: "{{ item }}"
    groups: wheel,slurm_admin
    append: yes
  with_items: "{{ sudoers }}"
```
