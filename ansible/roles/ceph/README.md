# CephFS Client Role

This role configures CephFS client mounting for shared storage access across the cluster. It mounts distributed filesystems that provide `/users` (home directories), `/software` (shared scientific software), `/data` (shared project data), and `/scratch` (temporary storage) to all nodes.

## Description

CephFS provides persistent, distributed shared storage for the SLURM cluster. This role:
- Installs CephFS client utilities
- Creates mount directories with appropriate permissions
- Configures authentication credentials
- Mounts CephFS filesystems persistently via /etc/fstab
- Sets special permissions for scratch filesystem (world-writable)

The mounted filesystems are accessible from all cluster nodes (controller, login, and compute nodes), enabling users to access their data consistently across the cluster.

## Requirements

- Ubuntu 22.04 LTS (Jammy Jellyfish)
- CephFS server already provisioned and operational
- Network connectivity to CephFS monitor and data servers
- `ceph-common` package (installed by common role)
- CephFS credentials and export location information from Terraform

## Role Variables

### Required Variables

The role requires `ceph_mounts` dictionary to be defined, typically generated by Terraform and stored in group_vars. Each entry describes a CephFS filesystem to mount.

#### ceph_mounts Structure

```yaml
ceph_mounts:
  <mount_key>:                      # Unique key (e.g., "home", "data", "software", "scratch")
    name: "<mount_name>"            # Name of the filesystem (used in secret filenames)
    mount_point: "<path>"           # Where to mount (e.g., "/users", "/data")
    export_locations:               # List of CephFS server addresses
      - "192.168.1.100:6789"        # Primary monitor/MDS address
      - "192.168.1.101:6789"        # Secondary monitor address
    access_key: "<ceph_secret>"     # CephFS access key (secret)
    access_to: "<client_name>"      # CephFS client identifier (e.g., "admin", "training")
```

#### Example Configuration

```yaml
ceph_mounts:
  home:
    name: "home"
    mount_point: "/users"
    export_locations:
      - "10.0.0.100:6789"
    access_key: "AQDk6GVkqWq... (secret key)"
    access_to: "training"

  software:
    name: "software"
    mount_point: "/software"
    export_locations:
      - "10.0.0.100:6789"
    access_key: "AQDk6GVkqWq... (secret key)"
    access_to: "training"

  data:
    name: "data"
    mount_point: "/data"
    export_locations:
      - "10.0.0.100:6789"
    access_key: "AQDk6GVkqWq... (secret key)"
    access_to: "training"

  scratch:
    name: "scratch"
    mount_point: "/scratch"
    export_locations:
      - "10.0.0.100:6789"
    access_key: "AQDk6GVkqWq... (secret key)"
    access_to: "training"
```

### Optional Features

The role automatically handles these special cases:
- **Scratch Filesystem** - When `mount_name == "scratch"`, permissions are set to 1777 (world-writable sticky bit) for temporary file sharing
- **Conditional Mounting** - Mounts only execute if `ceph_mounts` is defined

## Features

### CephFS Client Installation
- Installs `ceph-common` package for CephFS client utilities
- Provides kernel CephFS module support for optimal performance

### Secure Credential Management
- Creates `/etc/cephfs/` directory for credentials (mode 700)
- Stores access keys in individual secret files (e.g., `/etc/cephfs/home.secret`)
- Secret files are protected with restrictive permissions (mode 700)

### Persistent Filesystem Mounting
- Mounts each filesystem defined in `ceph_mounts` via Ansible `mount` module
- Adds entries to `/etc/fstab` for persistent mounting across reboots
- Uses mount options optimized for HPC: `noatime,_netdev`
- Supports multiple monitor addresses for high availability

### Directory Structure
- Creates mount point directories with appropriate ownership (root:root)
- Sets directory permissions: `u=rwx,g=rx,o=rx` (755) for standard mounts
- Sets world-writable permissions (1777) for scratch filesystem

### Mount Options

Filesystems are mounted with these kernel options:
- `name=<access_to>` - CephFS client identifier
- `secretfile=<path>` - Path to secret key file
- `noatime` - Disable access time updates (improves performance)
- `_netdev` - Treat mount as network device (mount after network is up)

## Dependencies

- **base** - Base OS installation (prerequisite)
- **common** - Installs ceph-common package dependency

This role must run after the common role, which installs `ceph-common`.

## Deployment Order

This role is part of the standard deployment sequence:

1. **base** - OS base configuration
2. **common** - Installs ceph-common and dependencies
3. **ceph** - This role (mount CephFS filesystems)
4. All subsequent roles can access mounted filesystems

## Installation Process

The role performs these steps for each mount in `ceph_mounts`:

### Phase 1: Credentials Setup
```bash
# Create credentials directory
mkdir -p /etc/cephfs
chmod 700 /etc/cephfs

# Write secret key to file (e.g., /etc/cephfs/home.secret)
echo "AQDk6GVkqWq..." > /etc/cephfs/home.secret
chmod 700 /etc/cephfs/home.secret
```

### Phase 2: Mount Directory Creation
```bash
# Create mount point with appropriate permissions
mkdir -p /users        # or /data, /software, /scratch
chmod 755 /users       # standard permissions
chown root:root /users
```

### Phase 3: Filesystem Mounting
```bash
# Mount via /etc/fstab
# Example line:
# 10.0.0.100:6789:/ /users ceph name=training,secretfile=/etc/cephfs/home.secret,noatime,_netdev 0 0

# Verify mount
mount /users
```

### Phase 4: Scratch Filesystem Special Handling
```bash
# If mount_name == "scratch", set world-writable permissions
chmod 1777 /scratch
```

## Verification

After this role completes, verify the mounts are active:

```bash
# List all mounts
mount | grep ceph

# Check specific mount points
df -h /users /software /data /scratch

# Verify mount points exist and have correct permissions
ls -ld /users /software /data /scratch

# Test write access to scratch (world-writable)
touch /scratch/test_$(date +%s).txt && rm /scratch/test_*.txt

# Check secret files are protected
ls -l /etc/cephfs/

# Verify fstab entries
grep ceph /etc/fstab
```

## Troubleshooting

### Mounts Fail to Mount

If mounts fail with "invalid argument" errors:

```bash
# Check CephFS client is installed
dpkg -l | grep ceph-common

# Check monitor addresses are reachable
ping 10.0.0.100

# Test mount manually
sudo mount -t ceph 10.0.0.100:6789:/ /mnt/test -o name=training,secretfile=/etc/cephfs/home.secret,noatime,_netdev

# Check CephFS server logs
ssh cephserver "sudo ceph -s"
```

### Permission Denied on Secret Files

If you see "permission denied" when mounting:

```bash
# Verify secret files have correct permissions (700)
ls -l /etc/cephfs/

# Check file content is correct (no extra spaces/newlines)
cat /etc/cephfs/home.secret | od -c

# Recreate secret file if needed
sudo echo -n "AQDk6GVkqWq..." > /etc/cephfs/home.secret
sudo chmod 700 /etc/cephfs/home.secret
```

### Mounts Not Persisting After Reboot

If mounts disappear after reboot:

```bash
# Check fstab entries
grep ceph /etc/fstab

# Remount using fstab
sudo mount -a

# Check systemd mount order
systemctl list-dependencies

# Ensure network is up before mounting
# (_netdev flag should handle this, but verify)
```

### Network Connectivity Issues

If mounts hang during boot:

```bash
# Check network is connected
ip addr show

# Check routing to CephFS monitors
route -n | grep -E "default|10\."

# Monitor boot messages
journalctl -u systemd-fstab-generator -n 50

# Mount with verbose output
mount -v -t ceph 10.0.0.100:6789:/ /users ...
```

### Scratch Filesystem Permissions Wrong

If scratch doesn't have world-writable permissions:

```bash
# Check actual permissions
stat /scratch

# Should show: Access: (1777/drwxrwxrwt)
# If not, set manually:
sudo chmod 1777 /scratch

# Re-run role to fix via automation
ansible-playbook site.yaml -i inventory.yml -t ceph
```

## Configuration

### Customizing Mount Points

To mount additional filesystems, add entries to `ceph_mounts` in group_vars:

```yaml
ceph_mounts:
  existing_mount: { ... }
  new_mount:
    name: "custom"
    mount_point: "/custom"
    export_locations:
      - "10.0.0.100:6789"
    access_key: "..."
    access_to: "training"
```

Then re-run the role to mount the new filesystem.

### Modifying Mount Options

To change mount options (e.g., add `max_bytes` limit):

Edit the mount options in `tasks/mount.yaml` line 42:

```yaml
opts: "name={{ access_to }},secretfile={{ secret_file_location }},noatime,_netdev,max_bytes=1099511627776"
```

Then re-run the role.

## Security Considerations

1. **Secret Keys** - Store in vault.yml with Ansible Vault encryption
   - Never commit plaintext keys to version control
   - Use `--ask-vault-pass` when running playbooks
   - Rotate keys regularly

2. **File Permissions** - Secret files use restrictive 700 permissions
   - Only root can read keys
   - Users authenticate via CephFS client automatically

3. **Network Security** - CephFS traffic should be on isolated network
   - Use security groups to restrict CephFS access
   - Consider network encryption for sensitive data

4. **Scratch Filesystem** - World-writable with sticky bit (1777)
   - Users can read/write/delete own files only
   - Cleanup policies should remove old files

## Common Issues and Solutions

### Issue: Mounts appear as "fuse" instead of ceph kernel client

This indicates the userspace FUSE client is being used. For better performance:

```bash
# Install ceph kernel module
sudo apt install linux-image-generic
sudo update-initramfs -u

# Reboot to load module
sudo reboot

# Remount
sudo mount -a
```

### Issue: Users cannot write to /scratch

```bash
# Verify 1777 permissions (sticky bit + rwx for all)
stat /scratch

# If wrong, role should fix it; if not:
sudo chmod 1777 /scratch

# Verify umask allows write access
umask
# Should show 0022 (default)
```

### Issue: Mount points missing after Ansible re-run

This is normal - Ansible `mount` module preserves existing mounts. If deleted manually, re-run the role.
