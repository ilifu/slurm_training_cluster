# Ansible Configuration for SLURM Training Cluster

This directory contains Ansible playbooks and roles that configure the OpenStack infrastructure (provisioned by Terraform) into a fully functional SLURM HPC training cluster. The configuration manages user authentication, job scheduling, shared storage, interactive computing environments, and web-based documentation.

## Architecture Overview

The SLURM training cluster consists of multiple interdependent services orchestrated by Ansible:

### Core Cluster Services
- **SLURM Controller** (`slurm_controller`): Central job scheduler and resource manager
- **Compute Nodes** (`slurm_compute`): Worker nodes for executing parallel jobs
- **Head/Login Node** (`slurm_headnode`): User entry point with JupyterHub and Caddy web server

### Supporting Services
- **LDAP Server** (`ldap`): Centralized user authentication and directory
- **SLURM Database** (`slurm_database`): MariaDB for job accounting and statistics
- **Shared Storage** (CephFS): Distributed filesystem for `/users`, `/data`, `/software`, `/scratch`
- **Web Services**: Caddy (reverse proxy) and JupyterHub (interactive notebooks)

### Service Dependencies
```
Base OS Configuration (base, common)
    ↓
LDAP Server ← installed first (users need it)
    ↓
LDAP Clients (all SLURM nodes)
    ↓
Shared Storage (CephFS mounts)
    ↓
SLURM Common (installed on all SLURM nodes)
    ↓
    ├─ SLURM Database ← depends on slurm_common
    ├─ SLURM Controller ← depends on slurm_common + database
    ├─ Head/Login Node ← depends on slurm_common + controller
    └─ Compute Nodes ← depends on slurm_common + controller + storage
    ↓
Web Services (Caddy, JupyterHub) ← optional, on login node
```

## Prerequisites

Before running Ansible, ensure you have:

### Control Machine (where you run ansible-playbook)
- **Ansible**: Version 2.10 or higher
  ```bash
  ansible --version  # Check installed version
  ```
- **Required Collections**:
  ```bash
  ansible-galaxy collection install community.general
  ```
- **SSH Access**: SSH keys from Terraform deployment must be loaded
  ```bash
  ssh-add /path/to/private/key.pem
  ```

### Target Infrastructure
- **Terraform Deployment**: All infrastructure must be provisioned first
  ```bash
  # From project root
  terraform apply
  ```
- **Generated Inventory**: `inventory.yml` is created by Terraform
  ```bash
  # Verify inventory exists
  ls -l inventory.yml
  ```

### Network Connectivity
- All nodes must be reachable via SSH from the control machine
- Floating IP or stable network access to login node
- Security groups configured to allow inter-node communication

## Configuration

### 1. Directory Structure

```
ansible/
├── site.yaml                    # Main playbook orchestrating all roles
├── ansible.cfg                  # Ansible configuration
├── inventory.yml                # Generated by Terraform (do not edit)
├── group_vars/
│   ├── all.yml                 # Variables for all hosts
│   ├── slurm.yml               # SLURM-specific variables
│   ├── ldap.yml                # LDAP-specific variables
│   └── vault.yml               # Secrets (encrypted with Ansible Vault)
├── roles/
│   ├── base/                   # OS base installation
│   ├── common/                 # Common packages for all nodes
│   ├── ldap_server/            # OpenLDAP server setup
│   ├── ldap_client/            # LDAP client configuration
│   ├── slurm_common/           # SLURM packages on all nodes
│   ├── slurm_controller/       # SLURM controller (slurmctld)
│   ├── slurm_headnode/         # Login node setup
│   ├── slurm_worker/           # Compute node configuration
│   ├── db_server/              # MariaDB for SLURM accounting
│   ├── ceph/                   # CephFS mount configuration
│   ├── caddy/                  # Reverse proxy web server
│   ├── jupyterhub/             # Interactive notebook environment
│   ├── jupyterlab/             # JupyterLab on compute nodes
│   ├── docker/                 # Docker container runtime
│   ├── manage_users/           # User account management
│   └── hosts/                  # /etc/hosts configuration
└── README.md                    # This file
```

### 2. Main Configuration File: `group_vars/all.yml`

Key variables you may need to customize:

```yaml
# Cluster identity
cluster_name: "ilifu-training"           # Cluster name for sinfo display
domain_name: "example.com"               # Domain for web services

# SLURM settings
slurm_version: "23.02.2"                # SLURM version to install
slurm_job_account: "training"           # Default job account
max_job_time: "01:00:00"                # Maximum job runtime

# LDAP configuration
ldap_host: "ldap.example.com"          # LDAP server address
ldap_base_dn: "dc=example,dc=com"      # LDAP base DN
ldap_organization: "ilifu"              # Organization name

# Features (set to false to disable)
install_docker: true                    # Install Docker on compute nodes
install_jupyterhub: true                # Install JupyterHub on login node
install_caddy: true                     # Install Caddy web server

# Storage locations
scratch_mount_point: "/scratch"         # CephFS scratch location
data_mount_point: "/data"               # CephFS data location
users_mount_point: "/users"             # CephFS home directories
```

See `group_vars/README.md` for complete variable documentation.

### 3. Secrets Management with Ansible Vault

Sensitive credentials (passwords, API keys) should be stored in an encrypted vault file:

**Create a vault file:**
```bash
ansible-vault create group_vars/vault.yml
```

**Example vault contents** (edit with `ansible-vault edit group_vars/vault.yml`):
```yaml
# LDAP Admin password
ldap_admin_password: "secure_password_here"

# SLURM Database password
slurmdbd_password: "database_password_here"

# SLURM API token (if needed)
slurm_api_token: "token_here"
```

**Reference vault variables in other files:**
```yaml
# In group_vars/all.yml:
ldap_admin_password: "{{ vault_ldap_admin_password }}"
slurmdbd_password: "{{ vault_slurmdbd_password }}"
```

**Running playbooks with vault:**
```bash
# Interactive password prompt
ansible-playbook site.yaml -i inventory.yml --ask-vault-pass

# Or use a password file (less secure)
ansible-playbook site.yaml -i inventory.yml --vault-password-file=.vault_password
```

### 4. Per-Role Configuration

Each role has its own variables in `group_vars/` and defaults in `roles/*/defaults/main.yml`. For detailed customization of individual services, see:

- `roles/slurm_controller/README.md` - SLURM scheduler configuration

- `roles/ceph/README.md` - Storage mount configuration
- `roles/caddy/README.md` - Web server and reverse proxy
- `roles/jupyterhub/README.md` - Jupyter notebook server

## Deployment

### 1. Verify Prerequisites

```bash
# Check Terraform has created infrastructure
terraform show | grep instance_ids

# Verify inventory was created
cat inventory.yml

# Test SSH connectivity to all nodes
ansible all -i inventory.yml -m ping
```

### 2. Syntax Check (Recommended)

```bash
# Verify playbook syntax without making changes
ansible-playbook site.yaml -i inventory.yml --syntax-check
```

### 3. Dry Run (Recommended)

```bash
# See what would be changed without applying changes
ansible-playbook site.yaml -i inventory.yml --check --ask-vault-pass
```

### 4. Full Deployment

```bash
# Run the complete configuration playbook
ansible-playbook site.yaml -i inventory.yml --ask-vault-pass
```

The playbook will run in this order:
1. Base OS installation on all nodes
2. Common packages and configuration
3. LDAP server setup
4. LDAP client configuration on cluster nodes
5. CephFS mount setup
6. SLURM common installation
7. SLURM database (MariaDB)
8. SLURM controller
9. Head/login node configuration
10. Compute node configuration
11. Optional: Docker, JupyterLab, JupyterHub, Caddy

### 5. Partial Deployment (Optional)

To run specific roles, use Ansible tags:

```bash
# Deploy only SLURM components
ansible-playbook site.yaml -i inventory.yml -t slurm --ask-vault-pass

# Deploy only LDAP
ansible-playbook site.yaml -i inventory.yml -t ldap --ask-vault-pass

# Deploy only storage
ansible-playbook site.yaml -i inventory.yml -t ceph --ask-vault-pass

# Deploy web services
ansible-playbook site.yaml -i inventory.yml -t caddy,jupyterhub --ask-vault-pass
```

Available tags:
- `base` - Base OS installation
- `ldap` - All LDAP (server + client)
- `ldap_server` - LDAP server only
- `ldap_client` - LDAP clients only
- `slurm_common` - SLURM common packages
- `slurmctld` - SLURM controller
- `slurmdbd` - SLURM database
- `slurm` - SLURM head node and workers
- `ceph` - CephFS storage
- `docker` - Docker runtime
- `jupyterhub` - JupyterHub
- `jupyterlab` - JupyterLab
- `caddy` - Caddy web server

## Verification

After deployment completes successfully, verify the cluster is functioning:

### 1. Login to Head Node

```bash
ssh ubuntu@<login_node_ip>
```

### 2. Check SLURM Status

```bash
# View cluster nodes
sinfo

# View node details
sinfo -Nel

# Submit a test job
sbatch --job-name=test --wrap="sleep 30"

# Check job status
squeue -u $USER
```

### 3. Verify LDAP

```bash
# List LDAP users
getent passwd | grep ldap

# Check if specific user exists
id <username>
```

### 4. Check Shared Storage

```bash
# Verify mounts
df -h | grep -E "/users|/data|/scratch|/software"

# Test write access to scratch
touch /scratch/test_file.txt && rm /scratch/test_file.txt
```

### 5. Test JupyterHub (if installed)

```bash
# Visit in browser: https://<domain>/jupyter
# Log in with cluster username/password
```

### 6. Check Service Status

```bash
# SLURM services
sudo systemctl status slurmctld
sudo systemctl status slurmd

# Database
sudo systemctl status mysql

# LDAP
sudo systemctl status slapd

# JupyterHub
sudo systemctl status jupyterhub
```

## Troubleshooting

### Common Issues

#### 1. Ansible Cannot Connect to Nodes
```bash
# Verify SSH key is loaded
ssh-add -l

# Test SSH directly
ssh -v ubuntu@<node_ip>

# Check security groups allow SSH (port 22)
```

#### 2. SLURM Nodes Not Appearing in sinfo
```bash
# Check slurmd is running on compute nodes
ansible slurm_compute -i inventory.yml -m shell -a "sudo systemctl status slurmd"

# Check slurmctld logs
sudo tail -f /var/log/slurm/slurmctld.log

# Verify network connectivity between controller and nodes
ping <compute_node_ip>
```

#### 3. LDAP Authentication Failing
```bash
# Check LDAP server is running
ansible ldap -i inventory.yml -m shell -a "sudo systemctl status slapd"

# Test LDAP connection
ldapsearch -x -h <ldap_host> -D "cn=admin,<base_dn>" -W

# Check LDAP logs
sudo journalctl -u slapd -n 50
```

#### 4. CephFS Mounts Not Available
```bash
# Check mounts on nodes
ansible slurm_headnode,slurm_compute -i inventory.yml -m shell -a "mount | grep ceph"

# Check CephFS secrets
sudo cat /etc/cephfs/home.secret

# Try mounting manually
sudo mount -t ceph <server>:/ /mnt/test -o name=<user>,secretfile=/etc/cephfs/secret.key
```

## Re-running Playbooks

Ansible is idempotent - running the playbook multiple times should be safe:

```bash
# Safe to run again to apply configuration changes
ansible-playbook site.yaml -i inventory.yml --ask-vault-pass

# Only update specific roles
ansible-playbook site.yaml -i inventory.yml -t ldap --ask-vault-pass
```

If you modify configuration variables, simply re-run the playbook to apply changes.

## Security Considerations

1. **Vault Passwords**: Store vault password file securely (not in git)
2. **SSH Keys**: Keep Terraform SSH private keys secure
3. **LDAP Admin Password**: Change from default in vault.yml
4. **Firewall Rules**: Ensure security groups restrict access appropriately
5. **Update Credentials**: Regularly update passwords in vault.yml
